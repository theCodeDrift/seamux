# Claude Code

Claude Code is the harness seamux was built around, and the one it knows best. seamux reads a Claude Code chat from three places: `claude agents --json --all` for which chats exist and their status, the chat's [transcript](transcripts.md) under `~/.claude/projects/` for what happened in it, and the [subagent hooks](subagents.md) it installs in `~/.claude/settings.json`. It drives a chat through cmux, launched through `cmux-claude-wrapper`, with the keys the `claude` entry in `HARNESSES` in [harness.server.ts](../app/lib/harness.server.ts) says it takes. Measured against Claude Code 2.1.281 to 2.1.286, as each entry says.

Most of what seamux knows about Claude Code belongs to a domain shared with other tools, so it lives there. This page gathers it, and holds what belongs to Claude Code alone. [Codex](codex.md) is the other harness, and differs from Claude Code almost everywhere.

## `claude agents --json --all` is the one list of every chat, and its rows differ by kind

It prints a JSON array with one row per chat on this Mac, in any terminal or none. An interactive chat's row has `sessionId`, `kind: "interactive"`, `cwd`, `name`, `pid`, `startedAt` (milliseconds) and `status`, which is `busy` or `idle`, or `waiting` with a `waitingFor` beside it. A background session's row has `kind: "background"`, a short `id`, and a `state` (`working`, `blocked`, `done` or `failed`), and loses its `pid` and `status` once its process is gone. Nothing in a row says what the chat is doing beyond that, so everything else comes from the transcript.

- **Measured:** Claude Code 2.1.286, for an interactive row; the background fields on 2.1.282.
- **In seamux:** `AgentRow` and `listAgents` in [board.server.ts](../app/lib/board.server.ts).
- **See also:** [Idle and waiting are separate `status` values](session-state.md#idle-and-waiting-are-separate-status-values), [A background session without a process is still listed](background-sessions.md#a-background-session-without-a-process-is-still-listed).

## A launch can choose the chat's session id and name

`claude --session-id <uuid> --name <name> '<prompt>'` starts a chat under that id and name, so seamux knows a dispatch's id before Claude Code reports it, and records the dispatch under it before the chat even starts. `--resume <id> --fork-session --session-id <uuid>` forks a chat under a new id the same way. Codex has neither flag, and a dispatch to it has to wait to learn its id.

- **Measured:** not recorded.
- **In seamux:** `dispatch` and `fork` in [drive.server.ts](../app/lib/drive.server.ts).
- **See also:** [A prompt given at launch waits for the trust dialog](codex.md#a-prompt-given-at-launch-waits-for-the-trust-dialog), Codex's version.
